# РИСсити Кликер — контекст проекта

Постоянный контекст для AI-агентов. Читать первым в каждой сессии, вместе с `MEMORY.md`.

`CLAUDE.md` и `AGENTS.md` обязаны оставаться точными копиями. При изменении правил обновлять оба файла в одной задаче.

Родительский проект: `../CLAUDE.md`, `../BRAND.md`, `../MEMORY.md`, `../prompts/mascot-prompts.md`. Правила родительского проекта действуют и здесь; настоящий файл их уточняет, а не отменяет.

## Что это

Браузерная игра-кликер для ресторана РИСсити (Красноярск, ул. 78 Добровольческой Бригады, 23).

Гость сканирует QR-код на столе, попадает в игру и тапает по маскоту Рисинке. Накопленные зёрна превращаются в процент скидки на счёт. На игру даётся один час реального времени; результат гость фиксирует у официанта.

- **Только мобильные устройства.** Десктоп не проектируем.
- **Основная аудитория — дети 6–12 лет.** Родители играют тоже.
- **Отдельный домен.** Деплой выполняет владелец на своём сервере (обязательно в РФ, требование 242-ФЗ).
- **Авторизации нет.** Сессия опознаётся по httpOnly-куке, состояние живёт на сервере.
- **Один QR на все столы.** Номера стола в ссылке нет.

## Продуктовые правила

| Правило | Значение |
|---|---|
| Максимальная скидка | 30%, заведомо недостижимый потолок |
| Длительность сессии | 60 минут по стенным часам, идут даже при закрытом браузере |
| Целевой средний результат | 10–15% за час |
| Скидка считается от | текущего баланса зёрен, покупка улучшения его снижает |
| Рестарт | новый час, попытки не ограничены |
| Фиксация | один раз за визит, после неё игра закрыта на 6 часов |
| Область скидки | весь чек, кроме алкогольной и табачной продукции |

## Жёсткие ограничения

1. **Никакой случайности в награде.** `Math.random()` запрещён во всём `src/game`. Случайный приз превращает акцию в стимулирующую лотерею по 138-ФЗ с уведомлением регулятора и отдельными требованиями. Все множители детерминированы.
2. **`Date.now()` запрещён внутри `src/game`.** Время приходит аргументом. Иначе экономику невозможно симулировать и тестировать.
3. **Пассивный доход только при видимой вкладке.** Иначе гость сканирует QR и уходит, а зёрна капают.
4. **Скидка не выдаётся деньгами** и не суммируется с другими акциями до отдельного решения владельца.

## Сервер авторитетен

Главное архитектурное правило: **клиент присылает намерение, считает сервер.**

- Клиент отправляет только количество тапов за окно синхронизации. Зёрна, скидку, время и лимиты вычисляет сервер и возвращает готовыми.
- Время всегда серверное. Часы телефона в расчётах не участвуют — перевод времени на устройстве ничего не даёт.
- Состояние лежит в SQLite, ключ — случайный идентификатор в httpOnly-куке. Из JavaScript кука недоступна, подделать её нельзя: сервер сверяет строку в базе.
- Клиент держит локальное предсказание теми же чистыми функциями из `src/game`, чтобы счётчик реагировал мгновенно. После ответа сервера клиент подтягивается к его состоянию. **Локальное предсказание — украшение, а не источник истины.**

Чего это НЕ даёт: скрипт, который честно шлёт запросы на максимальной разрешённой частоте, работать будет. Против него работает экономика, а не защита — пятнадцать тапов в секунду целый час упираются в 28%, а не в 30%. И скриншот чужого экрана по-прежнему возможен: одноразовых кодов для официанта нет по решению владельца.

**Расчёт скидки не размазывать по компонентам.** Вся математика живёт в `src/game/economy.ts` и одинаково исполняется на клиенте и на сервере.

### Устройство API

Одна точка входа — `src/app/api/session/route.ts`.

| Метод | Что делает |
|---|---|
| `GET /api/session` | Читает состояние, создавая сессию при первом заходе и выставляя куку |
| `POST /api/session` | Применяет действие: `start`, `tap`, `upgrade`, `finish`, `fix`, `restart` |

Тело POST — размеченное объединение, проверяется Zod. Неизвестные поля отбрасываются: подсунуть `grains` или `phase` в запросе невозможно.

Ограничители в `src/server/rate-limit.ts` защищают от обстрела, а не от накрутки. Операции над одной сессией сериализуются через `src/server/session-lock.ts` — иначе наложившиеся запросы теряли бы тапы в гонке «прочитал — посчитал — записал».

### Подводные камни Next 16

- `middleware.ts` переименован в **`proxy.ts`**, рантайм только Node, edge не поддерживается.
- `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()` — **только асинхронные**.
- `revalidateTag` требует **второй аргумент** с профилем `cacheLife`.
- Turbopack по умолчанию и для `dev`, и для `build`.
- `next lint` удалён, `next build` больше не линтует. Линт запускается отдельно через Biome.
- `serverRuntimeConfig` и `publicRuntimeConfig` удалены — только переменные окружения.
- Минимум Node 20.9, TypeScript 5.1.

### Про драйвер SQLite

`@libsql/client` с локальным файлом (`file:./data/app.db`). Готовые бинарники, нативная сборка не нужна.

`better-sqlite3` намеренно не используется: требует `node-gyp` и ломает установку без тулчейна. Встроенный `node:sqlite` тоже отпадает — Drizzle поддерживает его только с версии 1.0.0-rc, а на RC проект не сажаем.

Миграции — `drizzle-kit`. Перед первым запуском и после каждого изменения схемы нужен `pnpm db:migrate`. Тесты прогоняют те же миграции на базе в памяти, чтобы расхождение схемы не всплывало только в продакшене.

## Подход к UI/UX

### Визуальное направление

Тактильный, тёплый, «съедобный». Рис, дерево, керамика, ткань, мягкий естественный свет.

Брендбук РИСсити **прямо запрещает** неон, кислотные цвета, холодную синеву, стерильный глянец и плоский дешёвый вектор. Типовой кликерный «неоновый» язык под запретом. Сочность берётся из объёма, мягких тёплых теней, отскока и частиц зерна — не из свечения.

Все цвета только из `src/styles/_tokens.scss`. Хардкод hex в компонентах — ошибка.

### Правила тача (обязательны)

- Реакция на `pointerdown`, а не на `click`.
- `touch-action: manipulation` на интерактиве, `touch-action: none` на цели тапа.
- `user-select: none`, `-webkit-touch-callout: none`, `-webkit-tap-highlight-color: transparent` на игровых поверхностях (класс `.rc-tap-surface`).
- `preventDefault` на `gesturestart`: iOS Safari игнорирует `user-scalable=no`.
- **Зум страницы не блокируем.** Отключение масштабирования ломает доступность юридических страниц; двойной тап-зум снимается точечно на цели тапа.
- Мульти-тач разрешён: каждый `pointerdown` считается отдельно, дети тапают двумя пальцами.
- Цели касания не меньше `--rc-tap-min` (44px).
- `100dvh` вместо `100vh`, `overscroll-behavior: none`.

### Производительность

Горячий путь **не проходит через React**:

- частицы — один `<canvas>` с императивной системой и пулом объектов;
- счётчик обновляется через `store.subscribe` прямо в DOM-узел, дросселируется до кадра;
- анимация маскота — WAAPI или CSS-класс на узле, без ререндера;
- единственный `requestAnimationFrame`-цикл в `useGameLoop`, пассив пересчитывается на 10 Гц;
- запись в `localStorage` дросселируется: раз в 2 секунды плюс на `visibilitychange` и `pagehide`.

Бюджет: 60 fps на среднем Android, отклик на тап меньше 50 мс, JS главной страницы меньше 120 КБ gzip.

### Анимации

Переходы между экранами — React `<ViewTransition>`. Тайминги из токенов: 90–340 мс. Отскок — `--rc-ease-overshoot`. Всё уважает `prefers-reduced-motion`.

## Структура

```
src/
├── app/            маршруты, layout, api/session
├── game/           ЧИСТАЯ логика: без React, без DOM, без времени, без рандома
├── store/          Zustand: локальное предсказание и очередь тапов
├── features/       игровые блоки: tap-target, particles, hud, upgrades, legal
├── components/ui/  переиспользуемые примитивы
├── hooks/          useGameLoop, useVisibility, useSync
├── styles/         _tokens.scss, global.scss
├── server/         база, сессии, блокировка, ограничители
└── lib/            env, fonts
```

`src/game` не имеет права импортировать что-либо из React, `next/*` или DOM. Это проверяется глазами на ревью и является главным архитектурным правилом проекта.

## Правила разработки

- TypeScript строгий, включая `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.
- `any`, `unknown`, `never`, `as`, `!` — только с комментарием, объясняющим почему иначе нельзя.
- Импорты в начале файла. Inline-import только при документированной циклической зависимости.
- Константы вместо магических чисел. Вся экономика — в `src/game/constants.ts`.
- Файл больше 400 строк — сигнал к разделению.
- Комментарии только там, где объясняют неочевидное. Не пересказывать код.
- Тексты интерфейса на русском.
- Conventional Commits, проверяются хуком `commit-msg`.

## Балансировка экономики

Константы в `src/game/constants.ts` подбираются **симулятором, а не интуицией**. `src/game/simulator.ts` детерминированно прогоняет персон через реальный редьюсер, `economy.balance.test.ts` проверяет попадание в коридоры.

Текущий результат:

| Персона | Скидка |
|---|---|
| Ребёнок-казуал | 9% |
| Средний гость | 12% |
| Увлечённый ребёнок | 19% |
| Взрослый-максималист | 26% |
| Автокликер на 20 тапов/с | 28% |

Отдельно: ёмкость корзины тапов (`TAP_BURST`) заметно больше секундного лимита, потому что сервер получает тапы пачками раз в две секунды. При ёмкости, равной лимиту, честный быстрый ребёнок терял бы половину тапов на каждой синхронизации. Средний темп это не меняет — его задаёт скорость пополнения корзины.

Меняешь константу — прогоняешь `pnpm test`. Коридоры правятся только вместе с продуктовым решением, а не чтобы «тесты позеленели».

## Команды

```bash
pnpm dev            # разработка
pnpm build          # продакшен-сборка
pnpm typecheck      # tsc --noEmit
pnpm check          # Biome: формат + линт
pnpm check:fix      # то же с автоисправлением
pnpm test           # Vitest
pnpm test:coverage  # с покрытием и порогами
pnpm test:e2e       # Playwright на мобильных вьюпортах
pnpm verify         # всё сразу, перед сдачей задачи
pnpm db:generate    # миграции Drizzle
pnpm db:migrate
```

Хуки: на коммите — Biome по staged, `tsc`, затронутые юниты. На пуше — полный прогон тестов, сборка и e2e.

## Юридический каркас (РФ)

Черновики страниц лежат в `src/app/legal`, статус каждого пункта — в `docs/LEGAL-RU.md`.

**Юридические тексты не публикуются без согласования владельца и юриста.** Это правило родительского проекта, оно здесь не смягчается.

Минимальный набор: правила игры и акции с реквизитами ООО «Ортус Азия» (ИНН 2465369186, ОГРН 1252400017550), политика обработки персональных данных по 152-ФЗ, пользовательское соглашение, описание cookies с информирующим баннером, возрастная маркировка 0+ и реквизиты в футере.

Кука `rc_sid` — строго техническая: без неё игра не работает. В политике её нужно описать явно. В базе персональных данных нет намеренно: ни IP, ни user-agent, ни отпечатка устройства. **Не добавлять их «для аналитики»** — это расширит юридическую поверхность ради данных, которые проекту не нужны.
